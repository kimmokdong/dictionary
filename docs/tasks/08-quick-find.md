# 작업 지시 08 — 낱말 빨리 찾기 (대표 놀이)

`기획서_v2.md` 6-0절(놀이 공통)과 6-2절(낱말 빨리 찾기)을 읽는다. 사전 본체(넘김·색인·낱말 터치·글씨 크기·위쪽 띠·소리)는 이미 동작한다. 그 위에 놀이를 얹는다.

## 입력 데이터
- `data/games/quick-find.json`: 문제 세트 12개(쉬움·보통·어려움 각 4세트, 세트당 5문제). 문제 = `{ w, id, hint? }`. `id`는 한국어기초사전 항목 ID(entries의 `id`), `hint`는 동음이의어일 때 보여 줄 뜻 힌트. 이 파일은 **읽기만** 한다.
- 빌드 결과에는 항목 ID → 순번(seq) 대응이 없다. `npm run build:data`가 `data/games/quick-find.json`을 읽어 각 문제의 `seq`를 붙인 `data/build/games/quick-find.json`을 만들게 한다. 찾지 못한 ID가 있으면 빌드를 실패시킨다(문제 세트와 사전이 어긋나면 안 된다).

## 화면과 흐름
1. 위쪽 띠의 비워 둔 자리에 **"놀이"** 버튼. 누르면 띠 아래 패널에서 세트를 고른다(쉬움 1~4, 보통 5~8, 어려움 9~12). 세트마다 이 기기의 최고 기록을 작게 보여 준다.
2. 시작하면 띠 가운데에 **낱말 카드**(찾을 낱말, 동음이의어면 뜻 힌트 한 줄)와 **남은 시간**(100초부터 줄어듦), 문제 번호(1/5)가 보인다. 놀이 중에는 글씨 크기 버튼을 막는다.
3. 문제마다 책은 **첫 펼침(맨 앞)**에서 시작한다. 학생은 평소처럼 넘기고 색인을 잡아 찾는다. 넘김 동작은 그대로다.
4. 낱말 터치(지금의 짧은 터치 판정을 그대로 사용):
   - 정답 표제어면 그 항목을 표시하고 짧은 칭찬 → 1초 뒤 다음 문제.
   - 다른 낱말이면 멈추지 않고 작은 쪽지로 "이건 '○○'예요" 1.5초, 오답 횟수 +1.
   - 놀이 중에는 평소의 뜻풀이 쪽지를 띄우지 않는다.
5. 힌트: **30초**에 목표 낱말이 있는 색인 탭을 반짝이게 한다(옆면 캔버스에서 그 탭만 강조). **60초**에 길잡이 힌트("○○ ~ ○○ 사이에 있어요", 목표 쪽이 들어 있는 펼침의 길잡이 낱말)를 낱말 카드 아래에 띄운다.
6. **100초 제한, 포기 버튼 없음.** 시간이 다 되면 목표 펼침을 열어 그 항목을 2초간 표시하고("여기 있었어요") 다음 문제로.
7. 기록(문제마다): 걸린 시간 또는 시간 초과, 오답 횟수, 넘긴 횟수(완료된 넘김 수), 색인·옆면 묶음을 잡아 넘긴 적이 있는지.
8. 결과 화면(반대쪽 면 위 쪽지 크기 정도의 판, 화면 전체를 덮지 않음): 문제별 기록 표, 찾은 문제 수, 과정 위주의 칭찬 한두 줄(예: "색인을 써서 빨리 찾았어요", "틀려도 끝까지 찾았어요"). 빠르기만으로 순위를 매기지 않는다. 버튼: 다시 하기, 다른 세트, 사전으로.
9. 이 기기의 세트별 최고 기록(찾은 수 우선, 같으면 총 시간)을 `localStorage`에 저장한다. 새 기록이면 결과에 "새 기록!".
10. 놀이 중 띠의 "놀이" 버튼은 "그만하기"로 바뀐다(확인 후 사전으로). 기획서의 "포기 없음"은 문제 단위 이야기이고, 놀이 자체를 끝내는 것은 허용한다.

## 지켜야 할 것
- 넘김·색인·스냅·휘어짐 동작과 `src/geometry.js`는 바꾸지 않는다. 낱말 터치 판정 규칙도 그대로 쓴다.
- 놀이 로직은 새 모듈(`src/quickfind.js` 등)로 분리하고 `main.js`에는 연결 지점만 둔다.
- DOM과 무관한 로직(타이머 단계 판정, 기록 비교·저장 형식, 결과 문구 선택)은 `tests/`에 테스트를 붙인다.
- 프레임워크·새 의존성 금지. 코드 주석 한국어.
- `data/raw/`, `data/edits/`, `data/games/`, `기획서_v2.md`, `docs/` 수정 금지. 띄운 프로세스는 끝날 때 모두 종료. git 커밋 금지.
