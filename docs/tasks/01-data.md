# 작업 지시 01 — 사전 데이터 준비 (선별·정렬·조판)

전체 기획은 `기획서_v2.md`를 읽는다. 이 작업은 그중 10장 1단계와 3장·5장만 다룬다. 화면(프런트엔드)은 만들지 않는다.

## 목표

`data/raw/`의 원본 두 개로부터, 앱이 그대로 읽어 화면에 뿌릴 수 있는 "미리 조판된 사전"을 만드는 빌드 스크립트를 작성한다.

```
npm run build:data   # data/raw → data/build
npm test             # 정렬·조판 검증
```

## 입력 (읽기 전용, 수정·삭제 금지)

- `data/raw/nikl-vocab/vocab.xlsx` — 국어 기초 어휘 등급 목록. 마지막 시트 "전체(1~5등급), 40,000개"의 열: 등급, 어휘, 표준동형어번호, 품사, 어종, 원어, 의미, 분야. 품사는 `명사/부사`처럼 `/`로 여럿일 수 있다.
- `data/raw/krdict/krdict_json.zip` — 한국어기초사전 전체 JSON(11개 파일, 풀면 약 1GB, 표제어 56,555개). 구조는 `LexicalResource.Lexicon.LexicalEntry[]`. 각 항목은 `Lemma`(writtenForm), `feat`(homonym_number, partOfSpeech, vocabularyLevel, 원어 정보 등), `Sense[]`(definition, `SenseExample[]`, `SenseRelation`, `Equivalent[]`=외국어 대역). **`feat`은 객체일 때도 배열일 때도 있고, `Lemma`·`Sense`도 단일 객체이거나 배열일 수 있다.** 실제 파일을 열어 구조를 확인하고 작성한다.

압축을 풀어야 하면 `data/raw/krdict/extracted/`에 풀고 `.gitignore`에 넣는다.

## 해야 할 일

### 1. 선별
- 등급 목록 1~4등급 행만 대상.
- 낱말(표기)과 품사가 일치하는 기초사전 표제어를 찾는다. 품사 이름은 두 자료의 표기 차이를 확인해 대응표를 만든다.
- 후보가 여럿이면: 목록의 `원어`(한자·외래어 원어)와 기초사전의 원어 정보가 둘 다 있으면 그것으로 좁힌다. 좁힐 수 없으면 후보를 모두 싣는다.
- 기초사전에 없는 낱말은 싣지 않고, 목록(`data/build/report/unmatched.txt`)으로 남긴다.
- 같은 기초사전 표제어가 여러 등급 행에 걸리면 가장 낮은 등급을 쓴다. 표제어는 한 번만 싣는다.
- 속담·관용구 같은 부표제어, 외국어 대역, 발음 음원·이미지 정보는 뺀다.
- 예문은 뜻마다 최대 2개. 짧은 구·문장 예문을 우선하고 대화형 예문은 뒤로 미룬다.
- 유의어·반의어는 원본 `SenseRelation`에 있는 것만 싣는다.

### 2. 정렬
- 국어사전 자모 순서. (초성 ㄱㄲㄴㄷㄸㄹㅁㅂㅃㅅㅆㅇㅈㅉㅊㅋㅌㅍㅎ, 중성 ㅏㅐㅑㅒㅓㅔㅕㅖㅗㅘㅙㅚㅛㅜㅝㅞㅟㅠㅡㅢㅣ, 종성 순. 글자 수가 적은 쪽이 앞.)
- 표기가 같으면 기초사전 homonym_number 순. 어깨번호는 **수록된 것끼리 1부터 다시 매긴다**(하나뿐이면 번호 없음). 원본 번호는 따로 보존한다.
- 정렬 키 계산 방식과 한글 외 문자(띄어쓰기, 붙임표 등) 처리 방침을 코드 주석 한 줄로 남긴다.

### 3. 조판 (고정 지면, 줄 단위까지 미리 계산)
- 브라우저마다 줄바꿈이 달라지지 않도록, **빌드에서 줄바꿈까지 확정**한다. 앱은 계산된 줄을 그대로 한 줄씩 그린다.
- 글자 폭은 실제 폰트 파일의 글리프 폭으로 잰다. 폰트는 OFL 라이선스의 한글 서체(권장: Pretendard, Regular와 Bold)를 쓰고 폰트 파일과 라이선스 파일을 저장소에 둔다. 폭에는 2% 안전 여유를 둔다.
- 줄바꿈은 글자 단위. 줄 첫머리에 닫는 문장부호(`. , ) 」 ’ ”` 등)가 오지 않게 한다.
- 지면 수치는 전부 `data/layout.config.json` 한 파일에서 읽는다. 초기값:
  - 본문 영역 폭 510px, 높이 620px (한 쪽, 1단)
  - 글씨 단계 3개: `normal` 16px, `large` 18px, `xlarge` 20px. 줄 높이는 글씨의 1.55배
  - 표제어는 Bold, 본문보다 1.15배
  - 항목 사이 간격 0.5줄
- 한 항목의 모양: 첫 줄에 `표제어(어깨번호) [품사]` 뒤로 뜻풀이가 이어지고, 뜻이 둘 이상이면 ①②③ 번호. 예문은 뜻풀이 뒤에 구분 기호를 붙여 잇는다. 비슷한말·반대말은 마지막에.
- 쪽 넘김 규칙: 표제어 줄과 첫 뜻풀이의 첫 줄은 같은 쪽에 둔다. 항목이 쪽 끝에서 잘리면 다음 쪽으로 이어진다. 쪽 맨 위에 항목의 마지막 한 줄만 남는 경우(고아 줄)는 피한다.
- 각 쪽에 길잡이 낱말(그 쪽에서 **시작하는** 첫 표제어와 마지막 표제어)을 기록한다. 시작하는 표제어가 없는 쪽은 이어지는 표제어를 쓴다.
- 1쪽은 오른쪽 면에서 시작한다고 가정한다(쪽 번호 홀수=오른쪽). 자음 구간이 바뀔 때 쪽을 새로 시작한다.

### 4. 색인
- 색인 탭 14개(ㄱㄴㄷㄹㅁㅂㅅㅇㅈㅊㅋㅌㅍㅎ). ㄲ은 ㄱ, ㄸ은 ㄷ, ㅃ은 ㅂ, ㅆ은 ㅅ, ㅉ은 ㅈ 구간에 포함된다.
- 글씨 단계별로 각 자음 구간의 시작 쪽·끝 쪽·쪽 수를 기록한다.

## 출력 (`data/build/`)

구체적인 스키마는 직접 정하되 아래를 만족하고, `data/build/README.md`에 스키마를 적는다.

- `entries/` — 표제어 상세(ID, 표제어, 어깨번호, 품사, 등급, 뜻 목록과 예문, 관련어, 원본 ID). 여러 파일로 나눈다.
- `{normal|large|xlarge}/pages-NNNN.json` — 쪽 묶음(묶음당 40쪽 안팎). 쪽마다: 쪽 번호, 길잡이 낱말, 줄 목록. 각 줄은 텍스트 조각들과 그 종류(표제어/품사/뜻번호/뜻풀이/예문/관련어), 그리고 그 줄이 속한 표제어 ID. 표제어 터치 판정에 쓸 수 있어야 한다.
- `{단계}/index.json` — 전체 쪽수, 자음별 쪽 범위, 표제어 ID → 시작 쪽 대응(글씨 단계를 바꿀 때 위치 복원용), 쪽별 길잡이 낱말 요약.
- `report/summary.json` — 등급별 목록 수·수록 수, 동형어 처리 통계, 단계별 전체 쪽수와 자음별 쪽 수, 출력 용량.
- `ATTRIBUTION.md` — 두 원본의 이름·제공 기관·라이선스(공공누리 제1유형 / CC BY-SA 2.0 KR)·가공 내용.

## 테스트 (`npm test`, 모두 통과해야 완료)

- 정렬: 직접 고른 낱말 표본(쌍자음, 복합 모음, 받침 유무, 글자 수 차이 포함. 예: 가, 가게, 각, 간, 개, 고, 과, 괴, 까, 나)이 기대 순서로 정렬되는지.
- 전체 수록 표제어가 정렬 순서대로이고 중복이 없는지.
- 조판 불변식(세 단계 모두): 모든 표제어가 정확히 한 번, 정렬 순서대로 시작한다 / 어떤 쪽도 줄 수 한도를 넘지 않는다 / 어떤 줄도 폭 한도를 넘지 않는다(같은 폰트 측정으로 재검사) / 길잡이 낱말이 실제 그 쪽 내용과 일치한다 / 자음 구간이 빈틈·겹침 없이 1쪽부터 마지막 쪽까지 덮는다 / `index.json`의 표제어→쪽 대응이 실제와 같다.
- 원본에 없는 낱말·뜻풀이가 출력에 없는지(뜻풀이 문자열이 원본에 그대로 존재하는지 표본 검사).

## 건드리면 안 되는 것 / 제약

- `data/raw/`의 원본 파일과 `기획서_v2.md`, `docs/`는 수정하지 않는다.
- 뜻풀이·예문 문장을 고쳐 쓰거나 새로 지어내지 않는다. 원문 그대로.
- 프런트엔드 코드, 프레임워크, 번들러는 이 작업에서 추가하지 않는다. Node(ESM) 스크립트와 `node --test`만 쓴다. 의존성은 꼭 필요한 것(엑셀 읽기, zip 읽기, 폰트 측정)만.
- 스크립트는 `scripts/data/`에, 테스트는 `tests/`에 둔다.
- git 커밋은 하지 않는다.
- 코드 주석과 문서는 한국어로 쓴다.

## 끝나면 보고할 것

실행한 명령과 결과, 등급별 수록 수, 글씨 단계별 전체 쪽수와 자음별 쪽 수, 직접 정한 사항(품사 대응, 동형어 처리, 스키마)과 그 이유, 못 한 것.
