# 작업 지시 10 — 한 번에 펼치기 (두 번째 놀이)

`기획서_v2.md` 6-0절(놀이 공통)과 6-2a절(한 번에 펼치기)을 읽는다. 낱말 빨리 찾기(`src/quickfind.js`, 작업 지시 08)가 이미 동작한다. 같은 틀 위에 두 번째 놀이를 얹는다.

## 놀이 규칙
- 낱말 카드를 보고 **딱 한 번** 넘겨서(옆면 묶음·색인 탭·한 장 넘김 무엇이든) 목표 낱말이 있는 곳을 펼친다. 넘김이 끝까지 완료된 첫 번만 센다(놓아서 되돌아간 넘김은 세지 않는다).
- 한 판 10문제, 시간 제한 없음. 문제마다 책은 첫 펼침(맨 앞)에서 시작한다.
- 거리 = 목표 표제어가 있는 쪽이 펼친 두 면 안에 있으면 0, 아니면 펼친 면(L, L+1 중 있는 쪽)까지의 쪽 수 차이. 쪽은 지금 글씨 크기의 `index.entryPage[seq]`로 잰다.
- 점수(문제당 최대 10점, 한 판 100점): 거리 0 → 10점, 20쪽 이하 → 8, 60 이하 → 6, 150 이하 → 4, 400 이하 → 2, 그 밖 → 1. 구간은 나중에 조정하므로 상수 하나로 둔다.
- 쉬움(1~4세트): 지금 사전 그대로(색인 탭 사용 가능).
- 어려움(5~8세트): **색인 없이**. 색인 탭과 옆면의 구간 색 띠를 그리지 않고, 탭 잡기와 색인 스냅도 끈다. 옆면 묶음·한 장 넘김은 그대로.
- 두 단계 모두, 이 놀이 중에는 확대 창의 길잡이 낱말과 쪽 번호를 숨긴다(옆면 그림만 크게). 길잡이 낱말이 보이면 짐작하는 놀이가 아니게 되기 때문이다.

## 화면과 흐름
1. 위쪽 띠 "놀이" 버튼 → 패널에서 **놀이 고르기**(낱말 빨리 찾기 / 한 번에 펼치기) → 세트 고르기. 낱말 빨리 찾기의 세트 고르기·진행·기록은 지금과 똑같이 동작해야 한다.
2. 진행 중 띠 가운데 카드: 찾을 낱말, 문제 번호(3/10), 안내 "한 번에 펼쳐 보세요". 시간 표시는 없다. 글씨 크기 버튼은 막는다(빨리 찾기와 같음).
3. 넘김이 완료되면 더 넘길 수 없게 막고, 쪽지 판에 결과를 보여 준다: 거리 0이면 "딱 맞혔어요!", 아니면 "목표는 뒤쪽으로 ○쪽" / "앞쪽으로 ○쪽"과 점수. 버튼: **넘겨서 확인하기**, **다음 문제**.
4. "넘겨서 확인하기": 다시 자유롭게 넘길 수 있다(점수에는 영향 없음). 이때 낱말 터치는 빨리 찾기처럼 판정한다(정답이면 그 항목 표시와 "여기 있어요!", 아니면 "이건 '○○'예요"). 카드에 "다음 문제" 버튼을 보여 준다.
5. 넘기기 전(문제 시작 직후)의 낱말 터치는 무시한다. 놀이 중에는 평소의 뜻풀이 쪽지를 띄우지 않는다.
6. 결과 판(빨리 찾기 결과와 같은 크기·위치): 문제별 표(낱말, 거리, 점수), 총점/100, 과정 위주 칭찬 한두 줄(예: 20쪽 안으로 펼친 문제 수). 버튼: 다시 하기, 다른 세트, 사전으로.
7. 세트별 최고 점수를 이 기기 `localStorage`(`dictionary-openonce-v1`)에 저장, 새 기록이면 "새 기록!". 놀이 중 "놀이" 버튼은 "그만하기"(확인 후 사전으로).

## 데이터
- `data/games/open-once.json`(이미 작성됨, **읽기만**): 세트 8개, 세트당 10문제 `{ w, id }`. `level`은 "쉬움"/"어려움".
- `npm run build:data`가 빨리 찾기처럼 `seq`를 붙여 `data/build/games/open-once.json`을 만든다. `scripts/data/games.mjs`의 `linkQuickFind`를 놀이 이름을 받는 공통 함수로 바꿔 두 파일에 쓴다. 찾지 못한 ID는 빌드 실패. `data/build/README.md` 설명에도 추가.

## 구조
- 놀이 로직은 새 모듈 `src/openonce.js`. `main.js`에는 연결 지점만 둔다. 지금 `main.js`가 `quickFind.active / finding / tabHint / flipped / pick`을 직접 부르는 곳은 "지금 진행 중인 놀이" 하나를 부르게 정리한다(두 놀이가 같은 모양의 객체를 내놓게).
- 어려움 단계의 색인 끄기: `hitTest`에 선택 인자(예: `{ tabs: false }`)를 더해 탭 판정과 스냅을 건너뛰게 한다. 기본값 동작은 지금과 완전히 같아야 한다.
- 넘김을 막는 것은 `stage`의 `pointerdown` 진입 조건에서 처리한다.
- `?debug`에서 `window.__openOnce`로 상태 확인과 "목표 쪽으로 바로 펼치기"(넘김 완료로 처리) 정도의 시험 도구를 둔다.

## 지켜야 할 것
- 옆면 터치 규칙(`G`의 상수, `fineWeight`, `followEdge`, 넘김 시작 거리, 멈칫 판정)과 넘김 모양은 바꾸지 않는다.
- `data/raw/`, `data/edits/`, `data/games/`, `기획서_v2.md`, `docs/` 수정 금지. 새 의존성 금지, 코드 주석 한국어. 띄운 프로세스는 끝날 때 모두 종료. **git 커밋·푸시 금지.**

## 테스트(`tests/`)
- 거리 계산(펼친 면 안, 앞쪽, 뒤쪽, 첫 펼침처럼 한 면만 있는 경우), 점수 구간 경계, 기록 저장 형식·손상된 저장값 복구, 결과 문구 선택.
- `hitTest(..., { tabs: false })`: 탭 자리를 짚어도 탭이 아니고 스냅하지 않는다. 기본값은 기존 테스트 그대로 통과.
- 빌드 결과: 두 놀이 파일의 모든 문제에 `seq`가 붙고 사전 낱말과 맞는다.

## 완료 조건
- `npm run build:data` 성공, `npm test` 전부 통과.
