# 작업 지시 07 — 민감한 뜻 빼기

작업 지시 06(고친 예문 반영)이 끝난 상태에서 이어서 한다. 교사가 초등 사전에 맞지 않는 뜻(성·마약·자살·도박·낮잡는 말 등)을 빼기로 정했다.

## 입력
- `data/edits/remove-senses.tsv`: 한 줄 = `항목id-뜻id<탭>낱말<탭>이유`. 119줄. **읽기만** 한다.
- 항목 id·뜻 id는 `scripts/data/select.mjs`가 만드는 항목의 `id`, `senses[].id`와 같다.

## 할 일
1. 빌드의 선별 단계에서, **어깨번호를 매기고 정렬 순번(seq)을 정하기 전에** 목록의 뜻을 항목에서 지운다.
   - 뜻이 모두 지워진 항목은 항목째 뺀다(약 26개 표제어: 낙태, 마약, 자살 등).
   - 남은 뜻의 화면 번호(①②…)는 자연히 다시 매겨진다. 어깨번호도 남은 항목끼리 다시 매긴다(기존 규칙 그대로).
   - 목록에 있는데 찾지 못한 키는 빌드 끝에 출력하고 `report/edits.txt`에 적는다. `report/summary.json`에 `sensesRemoved`, `entriesRemoved`, `removeMissing`을 넣는다.
2. 작업 06의 예문 수정 적용은 그대로 동작해야 한다(지워진 뜻의 예문 수정은 건너뜀 목록에 넣지 말고 조용히 무시).
3. `ATTRIBUTION.md` 가공 내용에 "초등학생에게 맞지 않는 뜻 일부(N개)를 뺐다" 한 줄을 더한다. `index.html` "이 사전에 대하여"에도 짧게.
4. 테스트: 작은 가짜 데이터로 뜻 일부 삭제, 뜻 전부 삭제 시 항목 제거, 어깨번호 재부여를 확인한다. 실제 빌드 결과에 목록의 뜻이 남아 있지 않은지 확인하는 단언(`removeMissing` 0 포함). 원문 대조 테스트가 삭제를 허용하게 고친다.

## 지켜야 할 것
- 작업 06과 같다. `data/raw/`, `data/edits/`, `기획서_v2.md`, `docs/` 수정 금지. `src/` 변경 금지(`index.html`은 출처 문구만). 새 의존성 금지. 띄운 프로세스 종료. 커밋 금지.
