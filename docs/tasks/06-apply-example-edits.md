# 작업 지시 06 — 고친 예문을 빌드에 반영

`기획서_v2.md` 5-2절(예문 전수 검토)을 읽는다. Claude가 지면 예문 34,817개를 검토해 5,859개를 초등 눈높이로 고쳤다. 이 수정본을 데이터 빌드에 덮어써 넣는다.

## 수정본
- `data/edits/out/b01.tsv` ~ `b24.tsv`. 한 줄 = `키<탭>원문 예문<탭>고친 예문<탭>구분`. 머리줄 없음, UTF-8.
- 키 = `${항목 id}-${뜻 id}-${예문 순번 j}` (`select.mjs`의 항목 `id`, `senses[].id`, `senses[].ex[j]`).
- 원문 칸 표기: 원문 예문 끝에 공백이 있었으면 공백을 지우고 `␣` 한 글자를 붙여 적었다. 즉 대조할 값은 `x.replace(/\s+$/, '') + (x !== x.replace(/\s+$/, '') ? '␣' : '')`.
- 입력 묶음 `data/edits/batches/*.tsv` 중 한 줄(`71729-1-0`)은 원자료 뜻풀이에 탭이 섞여 칸이 하나 많다. 수정본에는 이 키가 없다.
- `data/edits/` 안의 파일은 **읽기만** 한다(수정·삭제 금지).

## 할 일
1. `npm run build:data`가 선별 뒤, 조판 전에 수정본을 적용하게 한다. 위치는 `scripts/data/`에서 알맞은 곳(새 모듈 `edits.mjs` 권장).
   - 키로 예문을 찾아 원문이 위 규칙대로 일치할 때만 고친 예문으로 바꾼다.
   - 키가 없거나 원문이 다르면 바꾸지 않고 목록으로 모은다. 빌드 끝에 개수를 출력하고 `data/build/report/edits.txt`에 적는다.
   - `report/summary.json`에 `examplesEdited`(적용 수), `examplesEditSkipped`(건너뜀 수)를 넣는다.
2. 고친 예문이 들어간 뒤 조판·쪽 묶음·index·entries·notes를 지금과 같은 방식으로 다시 만든다(3단계 글씨 모두).
3. 출처 문구를 고친다.
   - `ATTRIBUTION.md`(빌드 스크립트가 생성): "뜻풀이와 예문은 원문 그대로" → 뜻풀이는 원문 그대로, **예문 중 일부(적용 수)를 초등학생 눈높이에 맞게 고쳐 썼고 원문은 `data/edits/`에 보존**한다는 취지로.
   - `index.html`의 "이 사전에 대하여" 패널 문구도 같은 내용으로("뜻풀이는 원문 그대로, 예문 일부는 초등학생 눈높이에 맞게 고쳐 씀").
4. 테스트를 고친다.
   - `tests/data.test.mjs`의 원문 대조 테스트는 수정본이 적용된 예문을 허용해야 한다(같은 수정본 모듈을 써서 기대값을 만든다).
   - 새 테스트: 수정본 적용이 원문 불일치·없는 키를 건너뛰는지, `␣` 규칙이 맞는지(작은 가짜 데이터로).
   - 실제 빌드 결과에서 `examplesEditSkipped`가 0인지 확인하는 단언.

## 지켜야 할 것
- 뜻풀이, 표제어, 정렬, 조판 규칙, 앱 동작(`src/`)은 바꾸지 않는다. `index.html`은 출처 문구만.
- `data/raw/`, `data/edits/`, `기획서_v2.md`, `docs/`는 수정하지 않는다.
- 새 의존성 금지. 코드 주석은 한국어.
- 띄운 프로세스는 끝날 때 모두 종료한다. git 커밋 금지.

- `npm test` 전부 통과.
